BitLocker Global Auditor

Find - Fix - Prevent - Harden: recovery-key escrow & cipher strength across a hybrid Entra tenant

What this project does

Audits a hybrid Entra ID tenant for Windows devices whose BitLocker recovery key is not escrowed to Entra, remediates them at scale, prevents new gaps at provisioning time, and converts legacy AES-128 drives up to the AES-256 policy.

Queries Microsoft Graph for Windows devices and flags those with no BitLocker recovery key escrowed to Entra. The authoritative compliance metric for the whole project.

▶ Escrow remediation pair (Intune) FIX

An Intune Remediation that escrows missing keys to Entra and converges (runs once, then reports compliant).

The pair

  • Detect-BitLockerEntraEscrow.ps1 - read-only; non-compliant if a protected volume lacks a RecoveryPassword protector or has no recorded escrow.
  • Backup-BitLockerToEntra.ps1 - ensures a recovery protector, escrows with BackupToAAD-BitLockerKeyProtector, writes a success stamp to HKLM:\SOFTWARE\GI\BitLockerEscrow.

Hard-won lesson: Intune remediation scripts must be ASCII-only. One em-dash in a string failed all 153 devices in the first rollout ("The string is missing the terminator"). The Intune Management Extension mangles non-ASCII when it writes the script to disk.

▶ Cipher conversion AES-128 -> AES-256 HARDEN

Encryption method is locked when a drive is first encrypted, so drives encrypted before the 256 policy stay at XTS-AES-128. Detection reports them; PDQ converts them.

The scripts

  • Detect-BitLockerCipherStrength.ps1 - Intune detection-only; "With issues" = AES-128 population.
  • Install-BitLocker256ConversionTask.ps1 - staged by PDQ Connect (SYSTEM); registers a self-resuming scheduled task.
  • Convert-BitLockerTo256.ps1 - decrypt -> re-encrypt at 256 -> re-add TPM + RecoveryPassword protectors -> re-escrow. Idempotent, resumes across reboots, self-removes the task at 256.
Decrypt window: a cipher change requires a full decrypt first, so there is an unavoidable window with no BitLocker protection. Converter refuses to start without a ready TPM; throttle to small batches, prefer AC power, keep it to physically secure devices.
Not for TPM+PIN, network-unlock, or non-TPM devices. No clean rollback once decrypt starts - the safe direction is forward to 256.
Runbook: bitlocker-cipher-256-conversion-runbook.md

Key lessons

▶ Gotchas learned the hard way NOTES
  • Intune scripts must be ASCII-only - one em-dash failed all 153 devices.
  • Cipher strength is locked at encrypt time - policy does not retro-fix; escrow success is independent of cipher strength.
  • Cipher change has an unavoidable decrypt window - handle via TPM guard, throttling, PDQ task.
  • PSResourceGet -Reinstall deletes locked DLLs - use plain side-by-side install for updates.
  • Hybrid escrow target - hybrid devices default to on-prem AD DS; policy must save to Entra.
  • Device-side detection cannot confirm Entra receipt - the Graph auditor stays authoritative.
